# ADR-002: GNB 카테고리 ↔ NOVA 제품 매핑 & 범위 현실화

- **날짜**: 2026-07-29
- **상태**: accepted
- **결정자**: architect

## Context (맥락)

home.sb GNB는 **5카테고리 33항목**(분석 §1-2)이다: 그리드활용(11)·연계(2)·퍼포먼스(1)·활용방안(11)·데이터시각화(8). 이 분류는 **제품 기능(SBGrid/SBChart)과 응용(활용방안)이 섞여** 있다. NOVA 워크스페이스가 이 33항목의 breadth를 유지하되, **NOVA 제품 택소노미**(UX·UI·Grid·Chart·Dashboard·Doc, project_nova_platform 6제품)로 정돈해야 한다. 동시에 33항목을 당장 전부 구현할 수 없으므로 **범위를 현실화**하되, sbux처럼 "미준비 항목 클릭 → 준비중 alert"(분석 §2 반면교사)는 절대 금지다.

## Decision (결정)

**1) 카테고리 재편(5카테고리, 33항목 100% 흡수)**

| NOVA GNB 카테고리 | 주력 제품 | home.sb 대응(항목 수) |
|---|---|---|
| ① 통합 상황실 | Dashboard | 메인 대시보드 3탭 |
| ② 데이터 그리드 | Grid | 그리드활용 11 + 퍼포먼스 1 = 12 |
| ③ 데이터 시각화 | Chart | 데이터시각화 8 |
| ④ 업무 시나리오 | UX+Grid+Chart 조립 | 활용방안 11 |
| ⑤ 컴포넌트·연계 | UX + UI | 연계 2 |

→ 33항목(=3+12+8+11+2)이 5카테고리에 **매핑 손실 0**으로 흡수. NOVA UI는 셸(GNB/LNB) 자체에도 X-ray 태그로 노출, NOVA Doc은 상황실 "보고서 내보내기" 접점만(데모 없음, SBWrapDoc 정합).

> ⚠️ **ADR-005로 부분 정밀화(refine)**: 위 "NOVA UI = 셸 자체"에서 **셸 층③(멀티탭 바)만은 NOVA UI가 아니라 NOVA UX `TabWorkspace`(간판 기능)**로 재귀속됨(분석 §1-6 근거). 셸 크롬(프레임 바·GNB·LNB·푸터) = NOVA UI 귀속은 유지. 본 ADR의 카테고리 매핑·범위 현실화는 불변. 상세 = [ADR-005](005-tabworkspace-nova-ux-flagship.md).

**2) 범위 현실화 — 채움 14탭 + 미준비 비노출**

- **1차 채움 8탭**(전부 기존 자산 재사용): 홈·T1 상황실·T2 CRUD·T3 조건부서식·T6 차트갤러리·T7 지도·T9 급여·T12 컴포넌트·T14 UI템플릿.
- **2차 채움 6탭**(신규 소량): 그룹핑·대용량·통계시각화·정형조회·사원관리·리포트레이아웃.
- **GNB 서브메뉴에는 완성된 탭만 노출.** 미준비 항목(퇴직연금·보험설계·조직도 등)은 **문서 로드맵에만 존재, 화면 미노출**.
- 확장 서사는 홈 런처의 "추가 예정" **클릭 불가 카탈로그 카드**(캡션 "정식판 제공")로만 — ⛔ 준비중 alert 금지.

## Alternatives Considered (대안과 기각 사유)

| 대안 | 내용 | 기각 사유 |
|---|---|---|
| home.sb 카테고리 그대로 5개(그리드활용/연계/퍼포먼스/활용방안/시각화) | 벤치마크 라벨 복제 | NOVA 제품명과 불일치("퍼포먼스"가 단독 카테고리·"연계"가 모호). 제품 데모라는 정체성 흐림. **기각** |
| 33항목 GNB 전수 노출(미완성은 회색/준비중) | breadth 최대 과시 | sbux "준비중 alert" 반면교사 정면 위반. 17개 죽은 항목 = 신뢰 붕괴. **기각** |
| 제품 6개 = 카테고리 6개(UX/UI/Grid/Chart/Dashboard/Doc 1:1) | 제품 택소노미 순수 | "업무 시나리오"(활용방안 11)가 갈 곳 없음 — 조립 실무화면이 벤치마크의 절반. Doc은 데모 없음(빈 카테고리). **기각** |
| **5카테고리 재편 + 채움 14탭(채택)** | 제품+응용 2축 정돈, 미준비 비노출 | breadth 유지 + 제품 정체성 + 정직. **채택** |

## Consequences (결과)

**Positive**
- home.sb 33항목 breadth를 NOVA 제품 관점으로 재구성 → "제품이 어디 쓰이는지"가 카테고리로 드러남.
- 미준비 비노출로 정직 확보(신뢰 = 디테일).
- 1차 8탭이 전부 기존 자산 → 초기 구현 위험 낮음.

**Negative / Risks**
- 카테고리 라벨이 벤치마크와 1:1이 아니어서 벤치 대조 시 매핑표(설계 §3-2) 참조 필요 → 문서로 상쇄.
- "채움 14 vs home.sb 33" 수치 비교 시 breadth 열세 오해 가능 → breadth는 **실화면 수 + 카테고리 커버리지**로 반박(스텁 33 > 실화면 14 아님).
