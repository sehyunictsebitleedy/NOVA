## 0. 디자인 방향 선언

### 0-1. 정체성 문장 (이 사이트가 답해야 하는 질문)

> 방문자(개발자)가 3초 안에 알아야 하는 것: **"NOVA는 웹표준 프레임워크이고, 나는 지금 이 데모에서 컴포넌트를 만져보고 코드를 복사해서 내 프로젝트에 쓸 수 있다."**

- 벤치마크 실측이 증명하는 데모 사이트의 4요소(coverage-checklist §3-3): **① 실제 컴포넌트 렌더 ② 옵션 토글 ③ 코드 보기 ④ 코드 복사**. 이 4요소를 담는 단일 패턴("데모 유닛", §4)을 전 제품에 일관 적용한다.
- ⛔ 금지: "SEbit가 만든 서비스들" 전시·서비스 카드 갤러리·회사 소개 톤. 화면의 주인공은 **컴포넌트와 코드**다.

## 1. IA — 전체 구조

### 1-1. 구조 결정 (옵션 비교)

**결정 A. 제품 전환 수단**

| | A-1 상단 제품 탭 (권장) | A-2 좌측 제품 LNB |
|---|---|---|
| 구조 | GNB 아래 제품 탭바 5개 고정, 제품 내부 항목은 좌측 LNB | 좌측에 제품 5 + 하위 항목 트리 |
| 장점 | 벤치마크 관례(sbux/sbgrid/sbchart 모두 상단 제품·메뉴)와 일치 · "5제품 = 한 프레임워크"가 한눈에 · 모바일 축약 용이 | 트리 한 곳에 전부 |
| 단점 | 2단 내비(탭+LNB) | 제품 5×항목 40+ = 트리 과밀, 첫 인상에서 제품 라인업이 안 보임 |

**결정 B. 제품 내 데모 나열**

| | B-1 스크롤 스파이 (권장) | B-2 항목별 화면 전환 |
|---|---|---|
| 구조 | 제품 페이지 = 데모 유닛 세로 스택, LNB는 앵커+스크롤 스파이 | LNB 클릭마다 데모 1개씩 단독 화면 |
| 장점 | 훑어보기(스캔) 가능 — "이 제품에 이만큼 있다"가 스크롤 자체로 전시 · 구현 단순 · 검색(Ctrl+F) 동작 | 항목당 집중 |
| 단점 | 초기 DOM 큼(프로토타입 규모에선 무해) | 클릭 수 증가·전체량 체감 불가·SBUx 썸네일→개별 페이지 방식은 멀티페이지 사이트 전제라 단일 HTML에 부적합 |

**채택: A-1 + B-1.** 예외 — NOVA Dashboard(조립 데모 1개)와 NOVA UI(템플릿 카드 그리드)는 LNB 불필요, 전폭 레이아웃.

### 1-2. 화면 지도 (해시 라우팅)

```
#/            히어로(정문) + 제품 5 요약 진입 카드(제품 아이덴티티 스트립)
#/ux          NOVA UX   — 컴포넌트 데모 (LNB: 4카테고리 16항목)
#/grid        NOVA Grid — 동작하는 데이터 그리드 1 + 기능 토글 (LNB: 기능 6구획)
#/chart       NOVA Chart— 차트 8종 데모 유닛 (LNB: 카테고리 4)
#/dashboard   NOVA Dashboard — 조립 대시보드 1판 (전폭)
#/ui          NOVA UI   — 레이아웃 템플릿 4종 카드 (전폭)
```

- 제품 순서 고정: **UX → UI → Grid → Chart → Dashboard** (D4 명명 순서 = 기초부터 조립까지의 서사).
- LNB 앵커 예: `#/ux/button`, `#/chart/donut` — LNB 클릭 = 해시 갱신 + 스크롤, 새로고침 시 복원.

```
┌ GNB 60px ──────────────────────────────────────────────────────┐
│ ◆ SEbit NOVA  │ (보조내비) 가이드 · 예제 · 데모 │  v0.9 proto · 테마토글 │
├ 제품 탭바 48px ─────────────────────────────────────────────────┤
│  NOVA UX │ NOVA UI │ NOVA Grid │ NOVA Chart │ NOVA Dashboard    │
├──────────┬─────────────────────────────────────────────────────┤
│ LNB 240px│  제품 헤더(T1 + 포지셔닝 1줄 + Quick Start + 기능배지) │
│ 카테고리  │  ── 데모 유닛 스택 (§4) ──                           │
│ +항목    │                                                      │
└──────────┴─────────────────────────────────────────────────────┘
```

| 요소 | 스펙 |
|---|---|
| GNB | `--nova-bg-gnb`. 좌: 워드마크(20px, 앞에 4점 성좌 마크). 우: 보조내비 + 버전 칩(`v0.9 · prototype`, T5 outline) + 테마 토글 |
| **보조내비 3항목** (개발자 포털 정보구조 힌트 — 전부 실동작, 죽은 링크 금지) | **가이드** = 현재 제품의 Quick Start 스트립으로 스크롤 · **예제** = 현재 화면의 모든 코드 패널 일괄 펼침/접힘 토글(aria-pressed) · **데모** = 현재 사이트 자신(활성 고정 표시) |

| 제품 헤더 | 제품명(T1) + 포지셔닝 1줄(T4 sub) + **Quick Start 스트립** + **기능 배지 스트립**(§6 제품별) + 데이터 제품(Grid·Chart·Dashboard)만 `예시 데이터` sample 배지 1개 |
| Quick Start 스트립 | 인라인 코드 1줄 + 복사 버튼: `npm i @sebit-nova/ux` 식(제품별 패키지명). 코드 패널 미니 버전(§5) — "설치부터 시작"이라는 프레임워크 제품 문법 |

## 2. 히어로 (정문) — `#/`

- **레이아웃**: 좌 52% 카피 / 우 48% **터미널+코드 카드**(좌정렬 비대칭, G2). 배경 오로라 = 어제안 §3-3 스펙 그대로(radial 2겹 + blur 60px + opacity .22, reduced-motion 시 정지).
- **카피**:
  - Display: **"모든 시스템이 연결되는 새로운 웹 표준의 지평"** (세계관 정본 유지)
  - Sub(T4 sub): "NOVA는 컴포넌트·그리드·차트·대시보드·템플릿을 하나의 표준으로 묶은 웹표준 프레임워크입니다. 아래 데모의 모든 코드는 복사해서 바로 쓸 수 있습니다." — ⛔ "우리 서비스" 문구 금지, 수신자는 개발자.
  - CTA 2개: `[제품 둘러보기]`(primary fill → `#/ux`) + `[Quick Start 복사]`(outline — 클릭 시 설치 스니펫 클립보드 복사 + "복사됨" 피드백. 죽은 링크가 아니라 실제 동작하는 CTA).
- **우측 코드 카드** (히어로의 라이브 비주얼 = 서비스 미니 프리뷰가 아니라 **코드 그 자체**):
  - §5 코드 패널 스타일의 카드 1장. 내용 = 설치 2줄 + 사용 예 5줄(`<NovaButton>`·`<NovaChart type="line" ...>`), 우상단 복사 버튼.
  - 타이핑 커서 1개가 마지막 줄에서 깜빡임(2s 주기, reduced-motion 시 정지) — "살아있는 개발 현장" 최소 연출. 코드 자동 타이핑 애니메이션은 금지(과잉 연출 + 복사 UX 방해).
- **스탯 스트립**(히어로 하단, data-lg + T5): `5 Products · N Live Demos · 1 Standard`. **N = 빌드 시점 실제 데모 유닛 수를 계수해 표기**(JS `document.querySelectorAll('[data-demo-unit]').length`) — 발명 숫자 금지.
- 스탯 아래 **제품 아이덴티티 스트립**: 5제품 가로 카드(제품명 T3 + 한 줄 + 대표 미니 글리프 1개 — UX=버튼 윤곽·UI=레이아웃 와이어·Grid=표·Chart=라인 스파크·Dashboard=4분할). 클릭 = 해당 제품 진입. 서비스 카드 갤러리가 아니라 **제품 목차**다(설명 1줄에 서비스명 금지).

## 4. ⭐ 데모 유닛 패턴 (핵심 — 전 제품 공통 단일 패턴)

벤치마크 4요소(렌더·옵션·코드 보기·복사)의 NOVA 표준 구현. **이 패턴 하나가 사이트 전체의 문법**이다.

### 4-1. 구조와 치수

```
┌ 데모 유닛 카드 (bg-card · border · radius-lg) ────────────────────┐
│ ① 헤더 행 (h 48px · padding 0 20px)                               │
│    컴포넌트명(T3) · 유형수 배지(T5, 최대 1개) ······ [</> 코드] 토글 │
│ ├──────────────────────────────────── border ──┤                  │
│ ② 렌더 스테이지 (min-h 120px · padding 32px 24px · bg-page 침하)   │
│    ── 실제 동작하는 컴포넌트, 중앙 정렬 아님·좌상단 흐름 배치 ──      │
│ ③ 옵션 바 (border-top · h 52px · padding 0 20px · bg-card)        │
│    variant [세그먼트] · size [세그먼트] · disabled [스위치] …       │
│ ④ 코드 패널 (기본 접힘 · 펼침 시 max-h 320px 스크롤 · §5)          │
└──────────────────────────────────────────────────────────────────┘
```

| 항목 | 스펙 |
|---|---|
| ① 컴포넌트명 | T3. 우측 유형 수 배지(예: `4 variants`, T5 모노크롬 outline) — G10에 따라 배지는 이것 1개만 |
| ① 코드 토글 | ghost 버튼: `</>` 글리프 16px + "코드" 라벨(T5). `aria-expanded` + `aria-controls`. 펼침 상태 = primary tint 배경 + primary 텍스트. affordance: border(hover 시)+배경 반응 2종 |
| ② 렌더 스테이지 | 배경 `--nova-bg-page`(카드 대비 1단 침하 — "여기부터 렌더 영역" 경계를 톤으로), 내부 radius-md, **장식 0**(G8). 컴포넌트는 실사용 흐름대로 배치(버튼 3개면 가로 8px gap). 인터랙티브 상태 전부 실동작(hover·focus·active·disabled) |
| ③ 옵션 바 | 컨트롤 = **세그먼티드**(3택 이내 열거형: variant·size)·**스위치**(불리언: disabled·icon)·**셀렉트**(4택+). 라벨 T5 muted + 컨트롤. gap 20px, 우측 정렬 여백은 두지 않고 좌측부터 흐름 배치. 옵션 4개 초과 시 접이식 "옵션 더보기" 금지 — **대표 옵션 4개 이내로 큐레이션**(전수 옵션은 정식 Portal 문서 소관) |
| ④ 코드 패널 | §5. 펼침 애니메이션 = height 전환 `--nova-dur-base` + `--nova-ease`, reduced-motion 시 즉시 |
| 유닛 간 간격 | 24px. 카테고리 구획 사이 = 48px + 구획 헤딩(T2) |
| 앵커 | 유닛 루트에 `id`(예: `ux-button`) + 헤더 행 hover 시 `#` 앵커 링크 글리프(muted→primary) |

### 4-2. 상태·동기 규칙 (G9의 구현)

1. 데모 유닛의 상태 = 옵션 객체 1개(예: `{variant:'primary', size:'md', disabled:false}`).
2. 옵션 변경 → **렌더 재적용 + 코드 문자열 재생성**이 한 함수에서 일어난다(`render(state)` → DOM 반영, `codegen(state)` → 코드 패널 텍스트). 코드 하드코딩 문자열 별도 관리 금지.
3. 코드 패널이 접혀 있어도 상태는 유지 — 펼치는 순간 항상 현재 옵션과 일치하는 코드가 보인다.
4. 복사 버튼은 **현재 codegen 결과**를 복사한다(옵션 반영된 코드 = "내가 만진 그대로 가져간다" — 이것이 SBUx Copy Code의 상회 지점).

### 4-3. 복사 버튼 (전 사이트 공통 마이크로 패턴)

| 상태 | 시각 |
|---|---|
| 기본 | ghost: 복사 글리프 16px + "복사"(T5). 코드 패널 우상단 고정(스크롤 시 sticky) |
| hover | border `--nova-border-strong` + text 승격 |
| 복사 직후 | 글리프 → 체크(틸 `--nova-live-fg`) + "복사됨" 라벨, **1.6s 후 원복**. `aria-live="polite"` 영역에 "코드가 복사되었습니다" 통지 |
| 실패(클립보드 권한) | 글리프 → 경고 + "선택해서 복사하세요" + 코드 전체 선택 처리(폴백) |

## 5. 코드 패널 디자인 (+신규 토큰 — 본 문서 유일한 토큰 추가)

### 5-1. 원칙

- **코드 패널은 양 테마 공통 다크 고정.** 개발자 도구 관례이자, 라이트 모드에서도 "여기는 코드"라는 즉물적 구획. 단 패널 테두리·그림자는 테마를 따른다(라이트에서 떠 보이지 않게 border 1px + shadow-sm).
- 구문 강조는 4클래스만: 태그/키워드 · 속성명 · 문자열 · 주석. (토크나이저 단순화 + 색 절제 — 무지개 하이라이팅 금지.)

### 5-2. 신규 토큰 (부록 A에 추가분만 — 기존 팔레트 안에서 별칭)

```css
/* 코드 패널 전용 — 양 테마 공통(다크 고정) */
--nova-code-bg:      #0E0B1D;                  /* bg-gnb보다 1단 심층 */
--nova-code-fg:      #D8D4EA;                  /* 일반 코드 텍스트 */
--nova-code-tag:     var(--nova-primary-300);  /* #B3A3EC 태그·키워드 */
--nova-code-attr:    #7FA8EC;                  /* 속성명 (info 다크 fg 재사용) */
--nova-code-str:     #FBBF24;                  /* 문자열 (warn 다크 fg 재사용) */
--nova-code-comment: #8B84AD;                  /* 주석 (text-muted 다크 재사용) */
--nova-code-line:    #565073;                  /* 줄번호 — 비정보성 장식(대비 예외) */
```

**대비 검증(상대휘도 계산, bg `#0E0B1D` L≈0.0046 기준)**:

| 조합 | 대비 | 판정 |
|---|---|---|
| code-fg `#D8D4EA` | 12.6:1 | AAA |
| tag `#B3A3EC` | 8.6:1 | AAA |
| attr `#7FA8EC` | 7.4:1 | AAA |
| str `#FBBF24` | 10.5:1 | AAA |
| comment `#8B84AD` | 6.2:1 | AA+ |

### 5-3. 패널 구조

```
┌ 코드 패널 ────────────────────────────────────────────┐
│ 미니바 h36: `template` 라벨(T5 mono·muted) ···· [복사] │
│ ├─────────────────────────────────────────┤          │
│  1 │ <NovaButton variant="primary" size="md">        │
│  2 │   저장                                           │
│  3 │ </NovaButton>                                    │
│ 하단 캡션(T5 muted): 예시 API — 정식 시그니처는        │
│ NOVA Portal 문서 기준                                  │
└──────────────────────────────────────────────────────┘
```

| 항목 | 스펙 |
|---|---|
| 폰트 | `--nova-font-mono` 13px / 행간 20px, `tab-size:2` |
| 여백 | padding 16px 20px, 줄번호 열 폭 32px(선택 제외 `user-select:none`) |
| 라벨 | 미니바 좌측 코드 종류 라벨: `template`(SFC 컴포넌트) / `script`(옵션·데이터) / `terminal`(설치). 탭 2개 필요 유닛(Grid·Chart — 마크업+옵션 객체)은 미니바가 탭바 겸용: `template | script` |
| API 문체 | Vue SFC 자동 임포트 문체 — `<NovaButton>` `<NovaGrid :columns="cols" :rows="rows">` `<NovaChart type="donut" :data="data" alt="분기별 매출 비중">`. ⛔ 실존 확정 API처럼 완결 문서화 금지 — 하단 캡션 1줄로 정직 표기(프로토타입 전 패널 공통) |
| 접근성 | `<pre><code>` 시맨틱 유지, 패널 `tabindex="0"`(키보드 스크롤), 미니바 탭 `role="tab"` |

### 6-2. NOVA Grid — 동작하는 데이터 그리드 (`#/grid`)

- 포지셔닝 1줄: "엔터프라이즈 데이터 그리드 — 정렬·필터·편집·페이징이 웹표준 `<table>` 위에서".
- Quick Start: `npm i @sebit-nova/grid` · 헤더에 `예시 데이터` sample 배지.
- **핵심 = 데모 유닛 1개가 페이지의 주인공**(풀사이즈 그리드 1개 + 기능 토글 패널). 잘게 쪼갠 유닛 나열보다 "한 그리드에서 전 기능이 함께 동작"이 그리드 제품의 설득 문법(SBGrid 데모도 기능별 페이지지만 단일 HTML에선 통합 1판 + 토글이 우위).

```
┌ 그리드 스테이지 ──────────────────────────────────────────┐
│ 툴바: 전역 검색 인풋 · [행 추가] · [내보내기(정식판)]      │
│ ┌ 기능 토글 레일(우측 세로 200px) ┐  ┌ 그리드 본체 ──────┐ │
│ │ ☑ 정렬        ☑ 필터 행       │  │ sticky 헤더        │ │
│ │ ☑ 페이징      ☐ 첫 열 고정    │  │ 60행 × 7열         │ │
│ │ ☐ 셀 편집     ☐ 줄무늬       │  │ 페이저(10행/쪽)     │ │
│ │ ☐ 그룹핑(부서별 소계)         │  └───────────────────┘ │
│ └─────────────────────────────┘                          │
│ 옵션 바 대신 토글 레일이 역할 수행 · 하단 [</> 코드] 패널    │
└──────────────────────────────────────────────────────────┘
```

| 기능(토글) | 실동작 스펙 |
|---|---|
| 정렬 | 헤더 클릭 단일 정렬(▲▼ 글리프 + `aria-sort`), 재클릭 역순/해제 |
| 필터 | 헤더 아래 필터 행(열별 텍스트 인풋) + 툴바 전역 검색, 즉시 반영 |
| 페이징 | 클라 페이징 10행, 페이저 = 이전/다음+페이지 번호(tabular-nums) |
| 셀 편집 | **더블클릭 또는 Enter로 에디트 모드, 방향키로 셀 포커스 이동**(SBGrid 데모 원문 "방향키 이동+Enter 에디트" 재현 — coverage §2-2). 편집된 행 = 행머리 상태 칩 `U`(warn tint), 신규 행 = `I`(good tint) — 행 상태정보 데모 |
| 첫 열 고정 | `position:sticky; left:0` + 우측 경계 그림자 1px |
| 그룹핑 | 부서별 그룹 헤더 행 + 소계 행(급여 합계, tabular-nums) — Aggregates 미리보기 |
| 줄무늬 | 짝수행 `--nova-bg-surface` 20% tint |
| 내보내기 | 버튼은 두되 클릭 시 T5 툴팁 "Excel/CSV 내보내기는 정식판 기능입니다" — 죽은 척 금지, 정직 응답 |

- 기능 배지 스트립(제품 헤더): `Sorting` `Filtering` `Paging` `Cell Edit` `Sticky` `Grouping` solid / `Excel·CSV` `Virtual Scroll 10만행` `Tree` `Undo·Redo` `개인화` outline+정식판 (SBGrid 홈 배지 14종 문법의 정직 이분).
- 셀 타이포: `--nova-type-data-sm`(13/20) + tabular-nums, 행 높이 40px·헤더 44px(어제안 상수 승계).
- 코드 패널 탭 2개: `template`(`<NovaGrid :columns :rows sortable filterable :page-size="10">`) + `script`(columns 배열 정의 — 토글 상태가 속성으로 동기, G9).

### 6-3. NOVA Chart — 차트 데모 (`#/chart`)

- 포지셔닝 1줄: "SVG·Canvas 이중 렌더러 차트 — 42종 카탈로그의 대표 8종 데모" (42 = coverage §3-2 실측, 데모는 8종 정직 표기).
- Quick Start: `npm i @sebit-nova/chart` · `예시 데이터` sample 배지.
- **카테고리 4 × 데모 유닛 8종** (전 유닛 인라인 SVG 실렌더 — "NOVA Chart가 그린 것처럼" 축·눈금·범례를 갖춘 완성 차트로. ECharts 인라인 불가에 따른 프로토타입 구현일 뿐, 목업 티(손그림·플레이스홀더 회색 박스) 금지):

| 카테고리 | 유닛 | SVG 구현 요점 | 차트별 추가 옵션 |
|---|---|---|---|
| 라인형 | 라인 Line | polyline + 포인트 마커 + 호버 툴팁(수직 가이드선) | 스플라인(베지어) 전환 |
| 라인형 | 영역 Area | 라인 + 닫힌 path 채움(primary 12% tint — 그라디언트 채움 금지 G1) | 누적(stack) 전환 |
| 막대형 | 바 Bar | rect 시리즈 2그룹 + 호버 하이라이트 | 가로 전환(rotated)·스택 전환 |
| 원형 | 파이 Pie | arc path 5조각 + 호버 분리(2px 오프셋) | 값 라벨 표시 |
| 원형 | 도넛 Donut | 파이 + 내경 + 중앙 합계(data-lg) | 두께·중앙 라벨 |
| 원형 | 게이지 Gauge | 반원 arc + 바늘 + 임계 구간 색(good/warn/critical) | 값 슬라이더(실시간 바늘 이동) |
| 분포형 | 스캐터 Scatter | circle 40점 + 호버 좌표 툴팁 | 버블(반지름=제3값) 전환 |
| 기타 | 레이더 Radar | 5축 polygon 2시리즈 | 축 라벨·채움 |

- **공통 옵션 토글 5종**(SBChart 데모 옵션 10종의 대표군 — coverage §3-3): `축` `격자` `범례` `툴팁` `마커`. + **`[표로 보기]` 버튼**(접근성 — 동일 데이터의 `<table>` 다이얼로그, 어제안 §6-3 승계. SBChart SA 축 대응의 프로토타입 표현).
- 시리즈 컬러: 1=`--nova-primary`(테마별 400/600 자동), 2=`--nova-info-base`, 3=`--nova-live-base`, 4=`--nova-warn-base` — 시맨틱 팔레트 재사용(장식 무지개 금지). 색약 이중 채널 = 마커 모양 구분(●■▲◆).
- 축·격자선 = `--nova-border`, 축 라벨 = `--nova-text-muted` T5 + tabular-nums.
- 모든 SVG: `role="img"` + `aria-label`(데이터 요약문) — alt 계약(ADR-B3)의 데모 표현. 코드 예시에도 `alt` 속성 필수 노출: `<NovaChart type="donut" :data="sales" alt="분기별 매출 비중" />`.

| 폼(등록/수정) | 2열 폼 + 하단 액션 바 | Input·Select·Datepicker·Switch |
| 리스트/상세 | 좌 그리드 + 우 상세 패널(마스터-디테일) | Grid·Tabs·Badge |
| 설정 | LNB + 섹션 카드 스택 | Sidemenu·Switch·Accordion |

- **미리보기 = 실마크업 미니어처**: 템플릿 실제 HTML을 `transform: scale(.42)` + `pointer-events:none` + `overflow:hidden`으로 카드에 임베드(스크린샷 이미지 금지 — 토큰·테마 토글이 미리보기에도 그대로 적용되는 것 자체가 데모).
- 카드 액션 2개: `[크게 보기]`(모달 풀스케일 프리뷰 — 내부 인터랙션 동작) + **`[이 템플릿 복사]`**(primary — 템플릿 전체 마크업 codegen 복사, §4-3 피드백 동일).
- 카드 hover = 어제안 카드 인터랙션 승계(translateY(-2px) + border 승격 + shadow-md).

### 6-5. NOVA Dashboard — 조립 증명 (`#/dashboard`)

- 포지셔닝 1줄: "UX + Grid + Chart가 한 화면에서 함께 동작합니다 — 조립형 대시보드".
- Quick Start: `npm i @sebit-nova/dashboard` · `예시 데이터` sample 배지.
- **전폭 대시보드 1판**(12컬럼):

```
┌ 필터 바: 기간 셀렉트(월/분기/년) · 갱신 시각(T5 muted) · [X-ray] · [</> 코드] ┐
│ KPI 카드 ×4 (data-lg + 델타 ▲▼)                                             │
│ 매출 추이 라인차트 (8col)            │ 채널 비중 도넛 (4col)                  │
│ 주문 그리드 — 정렬·페이징 동작 (12col)                                        │
└─────────────────────────────────────────────────────────────────────────────┘
```

- **연동이 데모의 본질**: 필터 바 셀렉트 변경 → KPI·라인·도넛·그리드 **4위젯 동시 갱신**(갱신 위젯에 틸 플래시 600ms — 어제안 라이브 시각 언어 재사용). 그리드 행 클릭 → 도넛 해당 조각 하이라이트. 이것이 SBUx "강력한 연계성"(connectAllGridToComps — coverage §1-3)의 등가 전시.
- **X-ray 토글**(어제안 이식): ON 시 각 위젯에 1.5px 대시 아웃라인(primary-400) + 모서리 제품 태그(`NOVA UX` `NOVA Chart` `NOVA Grid`) — "이 화면의 어느 부분이 어느 제품인가"를 즉물 전시.
- 코드 패널 = 조립 코드 요약(`<NovaDashboard>` 슬롯에 `<NovaKpi>`·`<NovaChart>`·`<NovaGrid>` 배치 + 데이터소스 바인딩 1줄) — "위 제품들을 이렇게 조립한다"가 코드로 증명.

## 9. frontend 구현 가이드 (자체완결 단일 HTML)

### 9-1. 파일 구조

```
nova-product-demo.html
├─ <head> FOUC 방지 테마 복원 1줄 (localStorage 'sebit-theme' → data-theme)
├─ <style>  ① 토큰: 어제안 부록 A 전문 + §5-2 코드 토큰 추가
│           ② 베이스(리셋 · .t1~.t5 · .data-lg · tabular-nums 유틸)
│           ③ 셸(GNB·탭바·LNB·제품 헤더·푸터)
│           ④ 데모 유닛 공통(.demo-unit · .demo-stage · .demo-options · .code-panel)
│           ⑤ 제품별 스코프(.p-ux .p-grid .p-chart .p-ui .p-dash)
├─ <body>   히어로 + 제품 5 섹션(비활성 섹션 hidden — <template> 아닌 정적 마크업 허용,
│           단 Grid 행·차트 SVG는 JS 생성)
└─ <script> IIFE 1개 — state { theme, product, openCode:Set, demo별 옵션 객체 }
            해시 라우터 · 데모 유닛 레지스트리(render+codegen 쌍) · 클립보드 · 토크나이저
```

### 9-2. 구현 규칙

1. **토큰 강제**: 컴포넌트 CSS에 HEX 직접 사용 금지, 전부 `var(--nova-*)`. 예외 없음(서비스 씬이 없어졌으므로 어제안의 G6 예외도 소멸). grep 검사: 토큰 블록 외 `#[0-9a-fA-F]{3,6}` 0건.
2. **데모 유닛 레지스트리**: 유닛마다 `{ id, state, render(el,state), codegen(state) }` 등록. 옵션 컨트롤 변경 → 두 함수 동시 호출(G9). 코드 문자열은 codegen에서만 생성 — 정적 코드 하드코딩 금지.
3. **구문 강조**: 정규식 토크나이저 1개(태그 `</?[A-Za-z][\w-]*`·속성 `[\w-:@]+=`·문자열 `"..."`·주석 `<!-- -->` / `//`) → `<span class="tk-tag|tk-attr|tk-str|tk-cmt">` 치환. ⛔ 외부 하이라이터 금지. codegen 출력은 반드시 escape 후 토크나이즈(XSS·표기 깨짐 방지).
4. **클립보드**: `navigator.clipboard.writeText` + 실패 시 코드 영역 select 폴백(§4-3 실패 상태). 복사 텍스트 = 하이라이트 span 제외 원문.
5. **Grid**: 시맨틱 `<table>` + sticky 헤더. 데이터 = 60행 샘플 배열(부서·이름·직급·급여·상태 등 — 인명은 명백한 가명). 정렬/필터/페이징 = 배열 파이프(filter→sort→slice) 후 tbody 재렌더. 셀 편집 = 포커스 셀 교체 input, Esc 원복. 상태 칩(I/U)은 원본 대비 diff로 계산.
6. **Chart**: 인라인 SVG를 JS로 생성(viewBox 고정 `0 0 560 300`, 반응형은 CSS width 100%). 축 눈금 = "nice number" 계산(1-2-5 스텝). 호버 툴팁 = 단일 재사용 div(absolute). 게이지 슬라이더 등 옵션 변경 시 SVG 속성만 갱신(전체 재생성 최소화).
7. **테마**: `<html data-theme="dark">` 기본 + 토글 시 교체·저장(어제안 규칙 승계). 코드 패널은 테마 무관 고정 토큰이므로 전환 검증에서 제외 대상 아님(테두리는 변함 — 확인 필요).
8. **성능 예산**: 총 파일 ≤ 300KB · 외부 요청 0 · 상시 `setInterval` 0개(본 데모는 라이브 틱이 아니라 조작 반응형 — Dashboard 갱신 시각 표시만 이벤트 기반 갱신). 히어로 커서 깜빡임은 CSS 애니메이션.
9. **반응형**: 1280 / 1024(LNB→상단 칩) / 768(옵션 바 랩·Grid 가로 스크롤 컨테이너 + 스크롤 힌트 그림자) / 375(제품 탭 가로 스크롤·데모 유닛 패딩 16px). 터치 타깃 ≥ 44px.
10. **금지**: 외부 폰트/아이콘/하이라이터 CDN · 프레임워크 · 빌드 도구. 아이콘 = 인라인 SVG 스트로크 1.5px 자체 세트(복사·체크·코드`</>`·검색·화살표·닫기·테마·경고 등 최소 12종).
