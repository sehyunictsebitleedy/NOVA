## 0. 방향 선언 · 가드레일

### 0-1. 정체성 문장

> 방문자(개발자)가 각 사이트에서 3초 안에 알아야 하는 것: **"이건 NOVA {UX|Grid|Chart} 하나만을 위한 데모 사이트다. 항목마다 페이지가 있고, 만지면 코드가 바뀌고, 복사하면 내 것이 된다."**

- 어제 통합 탭과의 차이 = **폭이 아니라 깊이**. 항목 1개=페이지 1개(벤치 F1), 페이지마다 설명·조작 안내·API 표·레시피가 붙는다(F3·F4).
- ⛔ 제품별 액센트 컬러 발명 금지(Grid=파랑, Chart=초록 식 분화 금지). 3사이트 모두 **딥퍼플+오로라 단일 아이덴티티** — 컴포넌트 시스템 사이트도 단일 브랜드 컬러 강펀치가 수상권이라는 외부 실증(벤치 D8, Design System Yellow #FBC701 단일축·Awwwards HM)이 근거. 제품 구분은 워드마크 접미와 콘텐츠로만.

### 2-2. 사이트별 화면 지도 (해시 라우팅 공통)

```
nova-{제품}-demo.html

### 3-4. 코드 패널 상시화 규칙 (어제안 §5 위 델타)

1. 헤더 행의 `[</> 코드]` 토글 버튼 **제거** — 패널이 상시이므로 불필요. 대신 미니바에 `template|script` 탭 + 복사 유지.
2. G9 동기(옵션→렌더+코드 동시 재생성)·복사=현재 codegen 결과·복사 피드백(체크+aria-live)·실패 폴백 전부 승계.
3. 코드 패널이 뷰포트 밖일 때 옵션을 바꾸면 코드가 바뀐 것을 놓칠 수 있다 → TOC "코드" 항목 옆 6px 틸 도트 1.6s 표시(`--nova-live-base`, reduced-motion 시 생략) — 과잉 연출 금지, 도트 1개만.

### 3-5. 옵션 영역 규칙 (Nivo D6 그룹 탭)

| 옵션 수 | 형태 |
|---|---|
| ≤5 | 단일 옵션 바(어제안 §4-1 ③ — 세그먼티드/스위치/셀렉트) |
| 6~12 | **그룹 탭**: 탭바(T5, `role="tablist"`) + 그룹당 옵션 ≤5. 그룹명 표준: `기본`(핵심 변형) / `스타일`(시각) / `동작`(인터랙션) / `데이터`(Chart 전용 — 표로 보기·데이터 재생성) |
| 13+ | 금지 — 항목 페이지를 분할하라(전수 옵션은 Portal 문서 소관) |

- 그룹 탭 전환은 **옵션 상태를 리셋하지 않는다**(전 그룹 상태가 하나의 state 객체 — G9).
- Chart `데이터` 그룹 탭 안: `[표로 보기]`(어제안 §6-3 접근성 다이얼로그 승계) + `[데이터 재생성]`(시드 셔플 — 같은 코드가 다른 데이터에도 성립함을 전시). Nivo data 탭 동형(D6).

### 3-6. 대표 API 표 (sbux ⑦ 문법)

```
API                                        ── TOC 앵커 "api"
┌──────────┬─────────────────────┬────────┬──────────────────────────────┐
│ 속성      │ 타입                 │ 기본값  │ 설명 (1~2문장)                │
│ variant  │ 'primary'|'outline'… │ primary │ 버튼의 시각 위계. primary는…  │
│ loading° │ boolean              │ false   │ 스피너 표시+클릭 잠금         │
└──────────┴─────────────────────┴────────┴──────────────────────────────┘
캡션 T5 muted: ° = 정식판 범위 · 본 표는 예시 API — 정식 시그니처는 NOVA Portal 문서 기준
```

- **5~8행만**(데모에서 만질 수 있는 속성 우선 — sbux "대표 7행" 실측 문법). 전수 속성은 표로 두지 않는다.
- 정식판 행 = 속성명 뒤 `°` 위첨자 + 행 텍스트 `--nova-text-muted`(outline 배지를 행마다 반복하지 않음 — G10). 캡션에서 `°` 1회 해설.
- 옵션 컨트롤과 연결: 데모에서 만질 수 있는 속성 행은 hover 시 배경 `--nova-primary-tint` + 해당 옵션 컨트롤도 동시 하이라이트(표↔컨트롤 대응 학습 — 상회 디테일, 구현은 data-prop 매칭).
- 표 시맨틱: `<table>` + `<caption class="sr-only">` + `th scope="col"`. 모바일(768px 미만) = 타입 열 숨김(T5로 속성명 아래 병기).

├─ <body> 셸 정적 마크업 + <main id="app">(라우터가 렌더)
└─ <script>
    <!-- @nova-shared:core -->     라우터·레지스트리·codegen 토크나이저·클립보드·테마·계측 유틸
    (제품 고유)                     페이지 정의 registerPage(...) × N + 제품 렌더러
```

### 7-2. 공통 블록 마커 규약 (3파일 동기 — 옵션 1의 유지비 대책)

1. 공통 블록은 반드시 `<!-- @nova-shared:{name} -->` … `<!-- /@nova-shared:{name} -->` 마커로 감싼다. 마커 안은 **3파일에서 바이트 동일**해야 한다.
2. 검증(체크리스트 필수): 각 파일에서 마커 블록을 추출·해시 비교하는 검사 1회(스크립트 10줄 — diff 0 = 통과). 공통 블록 수정 = 3파일 동시 수정이 원칙.
3. 제품 고유 코드는 마커 밖에만. 마커 안에 제품 분기(`if (product==='grid')`) 금지 — 공통은 순수 공통.

### 7-3. 구현 규칙 (어제안 §9-2 승계 + 델타)

1. **토큰 강제**(승계): 토큰 블록 외 HEX 0건. **신규 토큰 0** — 본 설계는 기존 원장(쇼케이스 부록 A + 코드 패널 7종)만 사용한다.
2. **페이지 레지스트리(G11)**: `registerPage({ slug, cat, title, subtitle, summary, desc[], guide, options|groups, api[], recipes[], state, render(el,state), codegen(state), phase })`. 카탈로그 카드(summary+미니 렌더)·LNB·TOC·Prev/Next·title 전부 여기서 파생. 미니 렌더 = `render()` 결과 `scale(.55)` 임베드(별도 썸네일 자산 금지).
3. **어제 프로토타입 재사용 맵**(`nova-product-demo-prototype.html` 실측 행 기준):

   | 어제 블록 | 행 | 이관처 |
   |---|---|---|
   | ① 토큰 / ② 베이스 / ③ 소품 | l.13~160 | 3파일 `@nova-shared:tokens/base` (스테이지 테마 스코프 셀렉터만 추가) |
   | ⑤ 데모 유닛 공통 / 코드 패널 / ⑫ 표로 보기 / ⑬ 반응형 / ⑭ 모션 | l.224~276, 613~712 | `@nova-shared:demo/shell` — 유닛 카드가 "항목 페이지 스테이지"로 승격(코드 토글 제거 §3-4) |
   | ⑥ UX 스타일 + UX 유닛 16종 JS | l.277~423, 1165~ | `nova-ux-demo.html` — 유닛 1개 → 페이지 1개로 분해(checkbox/radio 분리 포함) |
   | ⑦ Grid 스타일 + 통합판 JS | l.424~478, 2113~ | `nova-grid-demo.html` — **렌더러 1개 유지 + 페이지별 프리셋 주입**(정렬 페이지 = sortable만 기본 ON…). 통합판은 `playground` 페이지로 생존 |
   | ⑧ Chart 스타일 + 렌더러 8종 JS | l.479~492, 1692~ | `nova-chart-demo.html` — 렌더러 8종 → 페이지 8개 + 신규(스텝·스택바·콤보·LTTB) |
   | ⑨ Dashboard / ⑩ UI / ⑪ 히어로 | l.493~612, 2415~2739 | **이관 안 함**(통합 쇼케이스 소관). 단 UX 연계 페이지가 ⑦⑧ 미니 렌더러를 차용 |
   | 라우터·GNB JS | l.2740~ | `@nova-shared:core` — 제품 탭 로직 제거, 항목 라우팅+포커스 이동으로 교체 |

4. **Grid/Chart 페이지 = 렌더러 공유 + 프리셋**: 기능별 페이지마다 그리드/차트 구현을 복제하지 않는다. 렌더러 1개 + 페이지 정의의 `state` 초기값·노출 옵션 구성만 다르게(G11) — sbgrid식 38페이지 확장도 정의 객체 추가만으로 가능한 구조.
5. **가상 스크롤(bigdata)**: 고정 행높이 40px 전제 windowing(스크롤 컨테이너 `overflow:auto` + 상하 스페이서 + 가시 구간만 tbody 재렌더). 계측 = `performance.now()` 두 지점(생성 완료·첫 렌더 완료), 표기 반올림 1ms. 50만 행 세그먼트는 disabled+정식판 툴팁.
6. **스테이지 로컬 테마**: 토큰 셀렉터 병기 방식(§4-1) — `:root, [data-stage-theme="light"] { … }` / `[data-theme="dark"], [data-stage-theme="dark"] { … }`. 스테이지 컨테이너에 `data-stage-theme` 세팅 시 하위만 전환. 전역 토글 변경 시 로컬 오버라이드는 유지(독립 축).
7. **LTTB**: 순수 JS 구현(~30줄, 외부 라이브러리 금지). 다운샘플 결과 포인트 수를 계측 패널에 실계수 표기.
8. 구문 강조·클립보드·escape 후 토크나이즈·성능 예산(상시 타이머 0)·반응형 4단·아이콘 인라인 SVG 세트 — 전부 어제안 §9-2 승계.
9. **P1/P2 단계 구현**: P1(재사용+분해+★2종+연계 1종)만으로 3사이트가 성립해야 한다. P2 항목은 레지스트리에 등록하되 카탈로그 카드에 `정식판`이 아닌 **`준비중` 미표기 — 아예 카드를 렌더하지 않는다**(⛔ sbux "준비중 alert" 반면교사 — 준비 안 된 항목은 목록에 올리지 않는 것이 정직. 단 전체량 문구는 "전체 N종 카탈로그는 정식 Portal" 캡션이 담당).
