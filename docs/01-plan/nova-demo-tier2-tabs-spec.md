## 0. 무엇을 왜 (한 줄)

**현 11탭 프로토타입(`nova-integrated-workspace.html`, 실측 191,152 bytes)에 6탭을 더해 17탭 워크스페이스를 완성한다** — home.sb 33항목 대응 커버리지의 잔여 축(그리드 집계·대용량 성능·SBChart 커버리지 잔여 7종·조회 패턴·인사 폼·리포트 장표)을 실화면으로 채워, "NOVA 5제품으로 실업무 화면 전 유형이 조립된다"는 증명을 완결한다.

**근거 사실 (실측·발명 0)**:
- 정본 ②-5 S2는 "11탭 전부 실화면" 판정이었음 — 마스터 확정(17탭)에 따라 **2026-08-03 정본 개정 완료**(변경 내역 = §8-2(a)).
- 설계 §4-1이 6탭의 카테고리·제품 귀속·자산 재사용을 이미 확정. 본 문서는 그 표를 벗어나는 탭·기능을 **추가하지 않는다**(스코프 이탈 0).
- 설계 §3-5-B(SBChart 커버리지 표)의 "채움 탭 = T8" 7행이 현재 미채움 — T8이 없으면 "SBChart 100% 커버" 주장의 실화면 근거가 비어 있다.

## 1. 사용자가 말한 것 / 내가 제안하는 것

**마스터가 확정한 것 (그대로 이행)**:

**내가 제안하는 것 [planner 제안 — 각 탭 절에 근거]**:

- B. **T8 범위 = 설계 §3-5-B 표의 "T8" 칸 7종 전부**(스텝·플롯·트리맵·데이터레인지·윙·barrange·areaRange). 한 줄 정의("레인지/스텝/버블")보다 넓으나, §3-5-B가 이미 T8을 채움 탭으로 지정한 커버리지 잔여의 전부다. orgchart 리치노드는 §3-5-B 원문대로 **제외**(로드맵 §4-3).
- C. **사원 원장 단일화** — T9(급여)와 T11(사원관리)이 같은 가상 인물 집합을 공유(단일 원장 원칙, 설계 §7 LEDGER 문법). 모순 인물 0.
- D. 구현 우선순위 = **T11 → T13 → T4 → T8 → T10 → T5** (§6, 가벼운 것부터 증분).

## 3. 탭별 기능정의

### T4 — 그룹핑·서브토탈 (② 데이터 그리드 · NOVA Grid)

**1) 왜 이 탭인가** — NOVA Grid의 **집계 구조** 역량 증명. softbowl 그리드활용의 grouping·subtotal·merge 3항목 대응(설계 §3-2 매핑표). 카테고리 내 차별: T2=편집(CRUD), T3=표현(서식·틀고정), **T4=구조(그룹·소계·병합)**, T5=규모(성능) — 그리드 4축 중 유일하게 빈 "집계" 축이다. 이 탭이 없으면 "업무 그리드"의 필수 요건(부서별 소계 장표)을 못 보여준다.

**2) 화면 구성**
- paneHead + local-bar(그룹 기준 선택 + 전체 접기/펼치기 + `.lb-note`)
- 본문 = 단일 카드 그리드 1개: **그룹 헤더 행**(그룹명 + 요약 칩 + 접기 토글) → 명세 행들 → **소계 행**(그룹 합계) → 최하단 **총계 행**. 동일 그룹 반복 값은 병합 표현(merge 대응).

**3) 데이터** — **신규 소형 원장 `LEDGER.ORDERS`**(가상 수주 명세 약 36~48행: 거래처·사업부·품목·월·수량·금액). 거래처명은 T2가 이미 쓰는 가상 거래처 집합(대성기계·한빛정공·동방전자·서진산업 등)을 재사용해 세계관 일관 유지. 사업부명은 LEDGER.DIVS 4종과 일치(단일 원장 원칙 — DIVS 분기 합계와 자릿수 규모가 모순되지 않게 파생·조정). exNote: "수주 명세 원장 (ORDERS)".

**4) 인터랙션** (전부 실동작)
- 그룹 기준 전환: 거래처별 ↔ 사업부별 ↔ 월별 (선택 즉시 재그룹·소계 재계산)
- 그룹 헤더 클릭 = 해당 그룹 접기/펼치기(소계 행은 접혀도 유지) · local-bar 전체 접기/펼치기
- 명세 행 수량/금액 셀 더블클릭 편집(C8) → **소계·총계 즉시 재계산**(라이브 파이프 증명 — 상황실 크로스필터와 같은 문법)

**5) 수용기준**
| # | 기준 | 판정 |
|---|---|---|
| S-T4-1 | 그룹 기준 3종 전환 시 그룹·소계·총계가 전부 재계산되고, 소계 합 = 총계 = 명세 합 (계산 정합) | 3기준 × 합산 대조 |
| S-T4-2 | 셀 편집 → 소속 그룹 소계·총계 즉시 갱신(리로드 없음) | 편집 전후 값 대조 |
| S-T4-3 | 접기 상태가 keep-alive로 보존(SC-3 구체화) | 접기 → 탭 왕복 → 확인 |
| S-T4-4 | 소계·총계 행이 시각+구조(aria) 양쪽으로 명세 행과 구분 | 마크업·대비 계측 |

**6) 예산** — **약 6KB** (그룹 파이프 JS + 그룹/소계 행 CSS + ORDERS 원장 ~2KB). 위험: 낮음.

**7) 재사용 vs 신규** — 재사용: T2 그리드 문법(gtable·정렬·셀 편집·pill)·nfmt·say. 신규: 그룹핑 파이프(정렬→그룹→소계 파생)·ORDERS 원장.

### T5 — 대용량 가상스크롤 (② 데이터 그리드 · NOVA Grid)

**1) 왜 이 탭인가** — NOVA Grid의 **성능(규모)** 역량 증명. softbowl 퍼포먼스 bigdata-binding 1항목 대응. 카테고리 내 차별: T2~T4는 수십 행 기능 데모 — 고객 실무 질문 "십만 행도 되나"에 답하는 탭은 이것뿐이다. SI 실무자 관점에서 그리드 제품 도입 판단의 1순위 질문.

**2) 화면 구성**
- paneHead + local-bar(행수 선택 1만/5만/10만 + 행 점프 입력 + **실 행수·렌더 성능 표시부**)
- 본문 = 카드 1개: 고정 헤더 + 가상 스크롤 뷰포트(전표 그리드). 하단 상태줄: "N행 중 i~j 표시 · DOM 행 k개" (전부 실계수).

**3) 데이터** — ⛔ **파일 임베드 금지 (예산 조항)**: 10만 행을 HTML에 박으면 행당 ~50-70 bytes로 **5~7MB → 예산(≤480KB) 즉시 파괴**. → **런타임 결정적 생성**을 요구한다: 시드 고정 PRNG로 로드 시 생성(같은 시드 = 같은 데이터 = qa 재검 가능). 프로토타입 내 선례 = T16 렌더러의 LCG(`seed=42`) — 같은 부류로. 컬럼 예: 전표번호·일자·거래처·품목·수량·단가·금액·상태(가상 값 조합). **정직 표기**: exNote를 "런타임 생성 예시 데이터"로 명기하고, 표시 행수 = 실제 생성 배열 길이(C10). 생성 알고리즘·자료구조 선택은 frontend 몫.

**4) 인터랙션**
- 행수 전환(1만/5만/10만) → 재생성 + 상태줄 갱신 (전환 중 UI 프리즈 없어야 — S-T5-2)
- 스크롤(연속 휠·드래그·키보드) · 행 점프(번호 입력 → 해당 행으로)

| S-T5-1 | 10만 행 선택 시에도 **DOM 행 노드 수가 상수 수준**(뷰포트 분량 + 버퍼, 예: ≤ 100)으로 유지 | DOM 계수(스크롤 전/중/후) |

### T8 — 통계 시각화 (③ 데이터 시각화 · NOVA Chart)

### T10 — 정형 조회화면 (④ 업무 시나리오 · NOVA UX+Grid+Chart)

### T13 — 리포트형 레이아웃 (⑤ 컴포넌트·연계 · NOVA UX+Grid)

  - **3종 시 "100% 커버" 주장에 생기는 구멍**: treemap·datarange·wing·barrange **4행의 채움 탭이 공석** → 100% 중 4종이 문서 주장으로만 남는다. 특히 **barrange는 ⚠️ custom 2종 중 하나** — native 종은 ECharts 공식 문서로도 방어되지만 **custom이야말로 실화면 실증이 필요한 지점**인데, 그 절반(barrange)이 빠져 "custom도 된다" 주장이 반쪽이 된다.
  - **예산·공수 차**: 7종 ≈ 9KB / 3종 ≈ 4~5KB[추정] — 잔여 예산 293KB 대비 무의미. 공수 차 = 소형 독립 SVG 드로어 4종 + AA 계측 셀 4개[추정 반나절~1일]. 실 병목(S-T8-4 채색 도형 위 라벨 AA 계측 왕복)은 3종이어도 동일 발생 — 트리맵·윙 제외로 AA 리스크가 줄어드는 것은 곧 증명 회피와 같은 말이다.
  - **문서 정합 비용은 3종이 더 크다**: 3종 선택 시 설계 §3-5-B 표 4행의 채움 탭 이송(로드맵행) + 커버리지 판정문 강등 + 본 스펙 S-T8-1 재작성 — architect 개정을 새로 유발. 7종은 현행 문서 그대로.
- **파급(한 줄)**: 7종 = 설계·스펙·수용기준 현행 유지(파급 0) / 3종 = 설계 §3-5-B 개정 + S-T8-1·정본 S4(X-ray 제품 귀속) 약화 + "100% 커버" 4종 강등.
- **[권고] ① 7종** — T8의 존재 이유가 커버리지 완결이며, 절감분이 실병목을 줄여주지도 않는다. (어느 쪽 확정이든 §4-1 한 줄 정의 ↔ §3-5-B 7행의 내적 불일치에 architect 정합 주석 1줄 요청.)
